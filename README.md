# Церковнославянский словарь

Мобильное приложение на Flutter для Android и iOS. Центр приложения — словарь; чтение с разбором и изучение языка развиваются вокруг словарных статей.

Рабочий идентификатор приложения: **`info.typikon.cs`**. Он задан как Android applicationId/namespace и iOS bundle identifier. Внутреннее имя Dart-пакета — `cs`, отображаемое имя — «ЦС Словарь». Это идентификатор приложения, не адрес backend.

## Текущее состояние

Создан начальный Flutter-каркас с экраном словаря, светлой и тёмной темами. Поиск, данные словаря, чтение и занятия пока не подключены. Демонстрационных словарных данных нет.

## Запуск

Используйте Flutter stable с Dart 3.12.2 или новее, совместимым с ограничениями `pubspec.yaml`.

```sh
flutter pub get
flutter analyze
flutter run
```

## Структура

- `lib/app/` — приложение, тема и будущая навигация.
- `lib/features/dictionary/` — основной словарный сценарий.
- `android/`, `ios/` — платформенные проекты.
- `audit/` — сохранённые отчёты и скрипты предварительного аудита данных.

По мере реализации слои данных и предметные модели размещаются внутри соответствующей функции приложения. Следующие самостоятельные функции — чтение и обучение.

## Данные и backend

Основной backend — соседний проект `typikon-web`: лексемы, формы, значения, схемы и учёт источников. Существующие ID должны сохраняться в приложении и локальном кеше. Прямой доступ мобильного клиента к MongoDB не используется.

Этимологии предоставляет `interlex`; приложение получает детали по ссылке на proto-статью. Редакторские исправления и импорт исходных словарей выполняются на backend. Частотные данные Chu-Rus различаются с собственными корпусными свидетельствами, реконструкции — с исходными данными.

Первый функциональный этап: поиск → словарная статья → формы и схемы → источники. Для церковнославянского текста переиспользуем проверенные шрифты приложения Уставных чтений.

## Локальные материалы

Архив `Chu-Rus_Reference_v3.dsl.dz`, базы, дампы, результаты аудита и содержимое `import/` исключены из Git и не включены в ресурсы приложения. Файлы остаются на диске. `integration/` — локальные копии уже перенесённого в `typikon-web` кода; они также исключены из этого репозитория.

Секреты, материалы подписи, сборки и кеши не отслеживаются. `pubspec.lock` сохраняется в Git для воспроизводимых зависимостей приложения.

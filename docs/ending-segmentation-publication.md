## Правила подтверждения

Основа и окончание выбираются из шаблона конкретной ячейки парадигмы. Конкурирующие основы других времён или форм не участвуют в выборе. Для склоняемых причастий используются основа самого причастия и его парадигма; причастные суффиксы не считаются падежными окончаниями. Возвратный постфикс передаётся отдельным сегментом.

Сводные причастные формы внутри глагольной парадигмы (`part*`) пока остаются без сегментов: остатки `лъ`, `ющи`, `емь` и подобные нельзя целиком объявлять окончанием. Склонение размечается в отдельных таблицах `participle-brev` и `participle-plen`, когда подтверждены основа и ячейка.

Граница принимается только при согласовании всего исходного написания с шаблоном и единственном допустимом разрезе между графемами. Ударения и надстрочные знаки в отображаемой строке не переписываются. Для сопоставления допускаются графические эквиваленты ука, юса, широких е/о; различия ъ/ь, е/ѣ, и/і и й сохраняются. Титла и выносные буквы, неизвестные схемы и несовпадающие формы остаются с `segments: null`.

Контрольные случаи:

| Форма | Подтверждённое окончание |
|---|---|
| воспо́льзꙋеши | еши |
| видотвори́ши | иши |
| безпеча́льномꙋ | омꙋ |
| краткая форма без̑печа́ленъ | ъ |
| дательный краткого причастия | ꙋ |
| дательный полного страдательного причастия | омꙋ |

Словарный вариант `без̑печа́лный` без ь не исправляется и не получает неподтверждённую границу от основы `безпеча́льн-`.

## Проверки и публикация

Обработано 34 119 карточек и 3 139 462 записи форм в ячейках. Изменились 26 580 карточек: добавлена разметка для 1 343 632 записей форм, снята неподтверждённая разметка с 49 557. Всего с сегментами — 2 267 771 запись, без сегментов — 871 691. Это записи форм, включая повторения по ячейкам и дополнительные написания, а не уникальные слова. Среди размеченных записей 1 207 664 относятся к причастным парадигмам.

Публикация создаётся отдельным файлом из неизменяемой исходной базы. Независимая проверка сравнивает каждую карточку, исключая только `paradigms[].slots[].forms[].segments`, и хеширует остальные таблицы. Каждая размеченная форма должна в точности восстанавливаться конкатенацией сегментов. Поисковые индексы, источники, редакторские решения и исходные формы не пересоздаются.

Морфемное содержимое сохраняется. Создаётся отдельная версия морфемной публикации с привязкой к новой версии словаря; обновляются только версия верхнего уровня и метаданные этой привязки. Обе базы проверяются через изолированный экземпляр API, затем переключаются одним systemd override. При ошибке проверки действующего сервиса скрипт автоматически возвращает прежнюю конфигурацию.

Скрипты: `tool/ending_release/`. Они используют приватный транспорт `import/lexical-release-20261109/remote.sh`; учётные данные в репозитории не сохраняются. `prepare.sh` начинает новую сборку, `resume.sh` предназначен только для незавершённого кандидата со статусом `building`, `validate.py` проверяет содержимое, `probe.sh` запускает изолированный API. Локальный `activate_local.sh` получает доступы через существующий приватный `release-target.sh` серверного репозитория и передаёт `activate.sh` по SSH с паролем sudo через stdin. `activate.sh` выполняет переключение с откатом. Повторная активация без новой подготовки намеренно блокируется проверкой исходных путей.

Итоговые версии, количества, хеши и результаты API-проверок сохраняются в `qa/ending-segments-deployment-result.json` и связанных отчётах.

Для ручного отката этого выпуска удалить только `/etc/systemd/system/typikon-web.service.d/zzzz-cs-ending-segments.conf`, выполнить `systemctl daemon-reload` и `systemctl restart typikon-web.service`, затем проверить версии API. Это применимо, пока последующие публикации не изменили конфигурацию. Старые файлы баз сохранены. Версия приложения и публичный каталог APK не меняются.

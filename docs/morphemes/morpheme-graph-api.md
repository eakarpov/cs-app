# API состава и этимологических цепочек морфемы

Реализовано и опубликовано 11 ноября 2026 года. Метод поддерживает `schema=2`; серверный master — `0ba4537`. Пример цепочки — редакционный проект на основании сохранённого описания ETYM-INF-NOMINAL, а не новая источниковедческая проверка.

## Маршрут и версии

Сохраняется единственный метод карточки:

`GET /api/v2/cs/morphemes/{id}?version={publicationVersion}&schema=2`

Не создаём дополнительные дублирующие `/details`, `/structure` и `/history`: карточка возвращает согласованные шапку, состав и граф одной версии. Список слов по-прежнему запрашивается независимо через `GET /api/v2/cs/morphemes/{id}/words?version=...&limit=20&cursor=...`. Он остаётся нужным и не объявляется deprecated. Получение морфем слова также сохраняется.

`version` — существующий непрозрачный идентификатор неизменяемой морфемной публикации. `schema` — версия представления карточки; это разные параметры. Изменение данных или структуры публикации требует нового `version`. Новый клиент всегда явно запрашивает `schema=2`.

Общие поля ответа сохраняются: `id`, `title`, `kind`, `gloss`, `status`, `version`, `statistics`, `allomorphs`. Новые обязательные поля: `schemaVersion: 2`, `composition`, `etymology`, `sources`. В ответе schema=2 отсутствуют устаревающие `structure[]` и `history[]`; это не два параллельных представления одних данных в одном ответе.

## Состав

`composition: {state, models, notes}`. `state = described | partial | undescribed`; состояние хранится редакционно, не считается простым наличием/отсутствием массива. `models` — отдельные модели состава, `notes` — описания, которым ещё не сопоставлена формальная модель.

Модель содержит:

- `id`, `title`, `level: synchronic | historical`, `allomorphIds[]` — обязательная область действия.
- `mappingMode: concatenative | fusion | unmapped`; `status`, `note`, `evidence[]`.
- `parts[]`: стабильный `id`, исходный `surface` (nullable), реконструкция `reconstruction` (nullable), `label`, `kind` (nullable), `function` (nullable), `status`, `note`, `evidence[]`, необязательная ссылка `target` на карточку морфемы.
- `alignment[]`: связь индексов графем выбранного алломорфа с `partIds[]`. Начало включительно, конец исключительно. При fusion несколько компонентов могут покрывать одну графему. Координаты относятся к конкретному алломорфу. При `unmapped` массив пуст; границы не придумываются.

Для `concatenative` конкатенация письменных `surface` должна в точности восстановить указанный алломорф с его надстрочными знаками; иначе модель не публикуется как concatenative. Объединять разные написания одной моделью можно только с отдельным проверенным alignment для каждого. Исторические части никогда не заменяют `parts` в морфемном разборе слова. Тип неизвестного исторического компонента — null, а не `inflection` по догадке.

## Этимология

`etymology: {state, nodes, relations, chains, notes}`. `state = described | partial | undescribed`. Все ссылки разрешаются внутри ответа или ведут на явно заданный внешний ресурс.

Узел: `id`, `label`, `form` (nullable), `reconstruction` (nullable), `formType: attested | reconstructed | descriptive`, `meaning` (nullable), `language`, `variety`, `period` (каждое nullable), `status`, `note`, `evidence[]`, `target` (nullable). Описательное «имя на *-ti-» не сериализуется как засвидетельствованная полная словоформа.

`language = {id, label}`. `variety = {label, type: recension | dialect | regional_variant, evidence[]}`; свободное происхождение классификации запрещено. `period = {label, fromYear, toYear, basis: attestation | reconstruction, evidence[]}`; неизвестные числовые границы — null, BCE — отрицательные годы, год 0 запрещён. Время реконструкции и время конкретного письменного свидетельства не смешиваются.

Связь: `id`, `fromNodeIds[]`, `toNodeId`, `type`, `label`, `status`, `note`, `evidence[]`. Типы: `origin`, `inheritance`, `borrowing`, `formation`, `reanalysis`, `grammaticalization`, `comparison`. Для направленных связей входы — предшествующие/образующие состояния, выход — результат; заимствование направлено от донора к реципиенту. Несколько входов в одной связи означают совместный вклад. Альтернативные объяснения размещаются в разных цепочках. `comparison` симметричен и не рисуется стрелкой происхождения. Если известен только общий факт происхождения, используется `origin`, без автоматического уточнения механизма.

Цепочка: `id`, `title`, `status`, `relationIds[]`, `focusNodeId`, `note`, `evidence[]`. Порядок relationIds не имеет исторического значения: порядок показа вычисляется из явно заданных связей. Общие узлы можно использовать в нескольких цепочках. Статус цепочки — статус редакционного утверждения; он не повышает статусы входящих связей. `proposed`, `disputed`, `approved` сохраняют текущие значения; проценты достоверности не вычисляются.

`notes` сохраняет исторические описания, для которых цепочка ещё не задана: `{id, title, text, reconstruction, status, evidence[], target}`. Из плоского старого history[] при миграции получается notes[], а не автоматически построенная цепочка. Указание на другую морфему само по себе не означает, что она предок.

Общий реестр `sources[]` в корне ответа используется составом и историей. `source = {id, title, publicationYear, kind}`; kind: `primary_attestation | scholarly_reference | editorial | unclassified`. `evidence = {sourceId, locator, quote, supports}`; quote nullable, supports — локальная формулировка того, что именно подтверждает ссылка. Публикационный год не участвует в датировке узлов. Первичное свидетельство и вторичная научная интерпретация различаются.

`target = {kind: morpheme, id}` либо `{kind: interlex, protoId, bodySha256}`; у interlex обязателен ожидаемый хеш, если он известен в редакторской привязке, иначе явно null. Все morpheme-ссылки открываются в той же морфемной публикации. При изменении interlex-редакции действует существующее предупреждение, данные не подменяются молча.

## Хранение и валидация

Канонические записи: модель состава и её компоненты/выравнивание; исторические узлы; связи; цепочки; источники и свидетельства. Это одна модель данных. SQLite-публикация сохраняет её готовой проекцией для карточки. Сохраняются исходные research ID, а стабильные публичные ID не зависят от текста заголовков и позиций в массивах.

Существующий `morpheme_etymology.components` — возможный источник моделей, если scope, соответствие и статусы явно проверены. Поля не восстанавливаются разбором строк `structure[].title` или `history[].reconstruction`. Записи без достаточных данных переходят в notes с точным сохранением текста, ссылок и статусов. Граф появляется только после редакционного задания узлов и связей.

Проверки перед публикацией: уникальные ID; разрешение ссылок; непустые входы; отсутствие повторных входов и ссылки узла на себя; отсутствие направленных циклов внутри каждой цепочки; comparison не участвует в проверке исторического порядка; все relations входят хотя бы в одну цепочку, все nodes используются в relations или как focus; morpheme targets существуют в той же версии; evidence ссылается на sources; approved-связь имеет хотя бы одно свидетельство, proposed/disputed может явно не иметь подтверждения. Предложенная связь не получает сплошную линию по статусу родительской карточки.

Валидация также проверяет графемное покрытие моделей, точное восстановление concatenative-форм, границы дат и наличие evidence у заявленного извода/диалекта/периода. Исходные словоформы, ударения и письменная сегментация не меняются. Граф не влияет на подсчёт связанных слов. Максимальный размер карточки — 512 KiB UTF-8: превышение блокирует публикацию карточки до согласования отдачи большого графа, без молчаливого усечения данных. Неизвестная история не заменяется пустым «доказанным» графом.

## Ошибки и кэширование

Сохраняются CORS, rate limit, ETag, Cache-Control и штатные ответы 400/404/409/503. Schema участвует в ключе ETag и кэша, как version.

- 400 `bad_request`: отсутствует version, неизвестная schema, неверный ID/курсор.
- 404 `not_found`: морфема отсутствует в выбранной публикации.
- 409 `schema_unavailable_for_publication`: сохранённая старая публикация не содержит schema=2; получить текущую версию через морфемы слова. Граф из её плоских текстов на лету не строится.
- 410 `schema_retired`: представление schema=1 снято с поддержки.
- 503 `unavailable`: публикация временно недоступна; существующая логика повторной загрузки.

Пустые состав и история — нормальный 200 со state=undescribed, а не ошибка. Страница слов использует прежнюю серверную сортировку, limit/cursor и семантику итогов.

## Deprecation и удаление legacy

Ненужных новых методов не вводим. Текущий метод карточки продолжает использоваться, поэтому его операция целиком не deprecated. Устаревает **представление schema=1**, включая плоские поля `structure` и `history`. В OpenAPI его схема и эти поля имеют `deprecated: true`; значение параметра schema=1 также отмечено deprecated. Существующий вызов без schema временно означает schema=1 и прямо документирован как deprecated.

План жизненного цикла:

1. Реализовать канонический schema=2 и временный чистый адаптер schema=2 → schema=1. Старое представление не имеет собственной базы и отдельных редакторских записей. Адаптер и старые DTO/экспортёры помечаются `@deprecated` с заменой и датой удаления. Адаптер реализован отдельно; новый клиент его не использует.
2. Первое стабильное приложение с этой карточкой запрашивает только schema=2. Перед его публичным выпуском дата прекращения schema=1 фиксируется в журнале API: **90 дней после фактического публичного выпуска**. Дата не считается от тестового APK и не остаётся плавающей. В журнале записываются замена, последняя поддерживающая версия приложения и задача удаления.
3. До этой даты выпустить ещё одну стабильную версию клиента, полностью убрать клиентские legacy-парсеры и проверить поиск морфем/карточку/пагинацию на schema=2. Учёт обращений к schema=1 — агрегатные счётчики без пользовательских данных. Счётчики помогают планированию, но не продлевают старый контракт автоматически.
4. В назначенную дату schema=1 и запрос без schema отвечают 410 `schema_retired`. Удалить адаптер, старые DTO/экспортёры/поля, legacy-ветки и их тестовые фикстуры. Остаётся один актуальный обработчик карточки; отказ для снятой схемы — проверка входного параметра, не поддержка старого метода. В дальнейших выпусках нельзя вернуть compatibility-код без отдельного решения. Новые публикации хранят только канонический состав и историю.

Если позднее появится реально лишний маршрут, его операция получает `deprecated: true`, явную замену и такой же конечный срок; одной пометки в комментарии недостаточно. Список слов и получение морфем слова сейчас не являются лишними и не получают ложную deprecation-пометку.

## Критерии готовности API

Новый ответ проходит JSON Schema и доменные проверки. Старый клиент до снятия schema=1 получает адаптированный текст без выдуманных границ и смены статуса. Новый клиент не зависит от structure/history. При снятии schema=1 адаптер физически отсутствует. На каждой опубликованной связи доступны её собственные статусы и свидетельства. Проверены цепочка из двух этапов, разветвление с совместными входами, альтернативные гипотезы, симметричное сопоставление, отсутствие датировок, чужая версия и недоступная interlex-редакция. Метод карточки не создаёт N+1 HTTP-запросов при первом показе схемы.

## Миграция существующих данных

Сборщик `tool/morpheme_schema2/build.py` создаёт новую неизменяемую публикацию поверх действующей; `canonical.py` подключён и к полному экспортёру `tool/morpheme_release/build.py`. Включены 16 моделей из существующих структурированных компонентов с проверенным allomorphId. Модель подключается только при точном совпадении исходного описания, источника, локатора и статуса с уже опубликованной карточкой. Нельзя незаметно подмешать более новые исследования. Модели без подтверждённого буквенного покрытия остаются unmapped. Из 44 исторических описаний получены notes; узлы и связи не выводятся из текста. Первичная классификация источников и годы неизвестны — `unclassified` и null.

Deprecated-ответ получает `X-Morpheme-Schema-Deprecated: true` и successor Link (включая 304); после назначения срока — Sunset. Конфигурация `CS_MORPHEME_SCHEMA1_SUNSET` задаёт ISO-момент снятия schema=1. Публичного приложения с новым экраном ещё не выпускали, поэтому дата не назначена по тестовой сборке. Задача удаления **RETIRE-MORPHEME-SCHEMA1**: при первом публичном выпуске зафиксировать дату +90 дней; затем удалить `legacyMorphemeCard`, ветку чтения schema=1 старых публикаций, LegacyMorphemeCard в схемах, старые DTO и фикстуры. Клиентский парсер structure/history уже удалён. Операция карточки, список слов и морфемы слова остаются актуальными.

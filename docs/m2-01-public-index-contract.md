# М2-01 Публичный доступ и версии мобильного корпусного индекса

15 ноября 2026 года. **Спецификация для реализации М2-02/04**, не опубликованный
API. APK и сервер этим шагом не менялись. Визуальная приёмка М1 остаётся
пользователю; выпуск кандидата 0.1.7+8 не объявляется публичным.

[Решения в JSON](mobile/m2-01-index-contract.json),
[приёмочные сценарии](mobile/m2-01-acceptance-cases.json),
[проверка текущего публичного namespace](../qa/mobile/m2-01-public-reader-audit.json).

## Что уже есть и чего пока нет

Локальная реализация Э1 содержит реестр источников/тел/вхождений, адреса v2,
паспорта, raw, токены, карты UTF-16 и три профиля проекции. ReaderService читает
существующие Mongo/певческую SQLite; Flutter содержит декодер ReaderReadPacket,
но пока не сетевой ReaderRepository и не подключённый мобильный reader.

Три обычных GET без аккаунта, ключа и подмены Origin/Referer к capabilities,
catalog и search на `https://www.typikon.info/api/v2/study/reader/v1/` получили
**404 без reader-envelope**. Этот публичный namespace пока не готов для М2.
Это не тест недоступности всех прежних портальных API и не отмена локальных Э1.

В локальном reader/http.ts вызывается общий authorize(texts). Он допускает
анонимное чтение scope texts, но общий anonymous allowance — **60 запросов
в час на IP**. Это общий бюджет, а не 60 запросов на каждый телефон. Подделывать
«свой сайт» браузерными заголовками или зашивать общий APP_KEY в APK не будем.

Нынешний ReaderService.search сканирует публикацию и строит проекции при запросе;
его indexRevision равен reader release ID. Это ещё не материализованный I01.
Lookup возвращает непроверенных кандидатов по словарному поиску, не подтверждённые
корпусные употребления лексемы. Восемь поисковых привязок М1-DATA-01 тоже не
переносятся автоматически в принятые связи токенов пилота: они могут быть
основанием кандидата, но требуют адресной проверки контекста. Наличие этих методов не закрывает М2-02.

## Решение о доступе

Для опубликованного пилота вводится **публичное чтение без обязательного аккаунта
и без ключа в APK**. Политика ограничена reader/v1 и его index-подразделом;
глобальные authorize, тарифы, прежний /api/v2/search и словарный API не перенастраиваются.
Неизвестный endpoint не включает обход старого API через legacy bulk-выгрузку.

- Обслуживается только явный опубликованный allowlist `cs-mvp-pilot-01`.
  Неопубликованные источники, редакторские изменения, публикация/активация,
  массовый экспорт и произвольное чтение native SQL/Mongo IDs здесь недоступны.
- Перед выдачей проверяется текущая видимость исходного текста/книги. Закрытый
  материал не читается через старую ревизию, старый cursor или локальный кеш.
  Native readiness и операторский допуск чтения — отдельные проверки.
- `chastny` акафиста не считается запретом публичного доступа: это поле исходной
  редакционно-богослужебной классификации, не ACL.
- Публичная доступность не означает свободную лицензию. sourceRights из Э1
  сохраняется; unknown не превращается в CC-BY-4.0. Право экспорта не выводится
  из наличия GET. Публикация фиксирует allowlist и основание допуска каждого материала
  (действующее публичное чтение портала/решение владельца); новый public reader
  по умолчанию не открывает весь портал.
- Для мобильного пути Authorization/X-Api-Key/Cookie не требуются и не отправляются.
  Bearer старых клиентов не получает права читать закрытое; обработка прежних
  ключей остаётся совместимой. Origin/Referer не дают повышенных прав публичному
  reader. POST resolve/read/lookup — операции чтения, не запись контента.

Начальные **проектные**, ещё не внедрённые и не измеренные нагрузкой лимиты:
общий бюджет reader/index **120 запросов/мин на IP**, внутри него search/occurrences
до **30/мин**, lookup до **30/мин**. Нового суточного лимита пилота нет. OPTIONS
не расходует прикладной бюджет; внешний потолок для префикса — 10 запросов/с,
burst 20. Общий IP оператора/NAT разделяет бюджет: не называем его лимитом устройства.
IP берётся только из доверенной цепочки reverse proxy, а не из произвольного
заголовка или installationId приложения. Сервер объявляет фактические значения в capabilities/заголовках, клиент их не
зашивает. 429 содержит Retry-After; нет автоматических циклических повторов.
Перед широким выпуском нужны измерения на реальном сервере и сценарий общего NAT;
само наличие квот не является результатом нагрузочной приёмки.

## Границы I01

Пять навигационных материалов Э1: P01 — крестовоскресный канон Октоиха,
P02 — акафист Николаю без молитв, P03 — первая беседа Маргарита, P04 — ссылочный
ирмос в P01, P05 — тропарь «Правило веры». Это **не пять независимых произведений**.
По локальному срезу Э1: 68 навигационных units и ожидаемо 67 различных размещений,
поскольку P04 показывает одно из размещений P01. Числа — контрольная база для
перепроверки в М2-02, не результат уже построенного production-индекса.

| Канал | Что утверждает | Чего не утверждает |
| --- | --- | --- |
| word/phrase | Совпадение ключей токенов в конкретном теле | Идентичность лексемы, смысла или разбора |
| lexeme | Принятая адресная связь token/placement → lexemeId с основанием | Все словоформы/омонимы разобраны автоматически |
| candidate | Хранится отдельно для проверки; в первую выдачу подтверждённых употреблений не входит | Совпадение формы уже принято редактором |

Первая поставка поддерживает folded и abbreviation_skeleton с явным matchKind;
строгое графическое exact не объявляется без отдельной реализации. Word ищет один полный токен, не префикс и не подстроку; phrase — от 2 до
12 последовательных допустимых токенов одного body; переходов через тела,
сноски или рубрики нет. Пунктуация обрабатывается только по версионированному
профилю. Текст сносок, рубрики и сканы отдельно не индексируются в первом I01.
Числовой кандидат остаётся числовым, а не автоматически лексемой. Пустой после
токенизации запрос — 400; неразрешённая графика запроса — явный 422, не ложный нулевой результат.

Неразрешённый PUA блокирует весь соответствующий поисковый токен; нельзя индексировать
обрезанный остаток слова или удалить токен и склеить фразу через этот разрыв. В coverage отдельно показываются охват тел, доступных
поиску токенов и подтверждённых лексемных связей. Пустой ответ означает «не найдено
в доступной поиску части пилота», не «не встречается во всём корпусе».

Дублирование устранено по **размещению**, а не по одинаковым буквам:

- bodyId/bodyRevision/tokenId и проекция формулы переиспользуются;
- occurrenceId обозначает размещение; в Э1 P04 уже использует родительский P01;
- `hitId = hash(occurrenceId, bodyId, bodyRevision, ordered tokenIds)`;
  matchKind и навигационный alias не создают новое физическое употребление;
- P01/P04 дают один hit с каноническим адресом размещения P01 и двумя
  navigation aliases. Настоящие разные размещения одной формулы считаются отдельно;
- repeatCount рубрики не умножает число записанных текстовых употреблений;
- владелец хранимого тела ирмоса и его исторический родной канон — разные связи.
  Неизвестный originalPartOf остаётся неизвестным.

## Версии и адреса

Reader сохраняет `/api/v2/study/reader/v1/`, `contract=cs-reader/1` и
SourceAddress.version=2. Для I01 выделяется вложенный read-only namespace
`.../index/` с envelope **`contract=cs-index/1`**. Это не второй реестр текстов
и не новый формат постоянного адреса. Старый Flutter ReaderReadPacket не получает
index-DTO вместо read-пакета; для индекса нужен отдельный декодер в М2-04.

| Обозначение | Смысл |
| --- | --- |
| C | Существующий reader release1_: состав пилота, sourceRevision/passportRevision и dataset revisions |
| I | Новый ix1_: неизменяемый манифест индексной публикации, связанный с C, D, профилями, postings и принятыми связями |
| D | Публикация словаря из карточки М1; базовый срез сейчас caa7…08b5b |
| P | Точный profileSetId и fingerprint правил/таблиц/Unicode; не только display-настройка |
| body/token/map | Существующие br1/tok1/map1/proj1 из Э1; смещения полуоткрытые UTF-16 |

I — SHA-256 canonical manifest: C, ordered body revisions, fingerprints профилей,
хеши postings, версия дедупликации/поиска, D и ревизии принятых лексемных связей.
Изменение паспорта, D или правил создаёт новый manifest I, но **не требует копировать
тексты или заново строить неизменившиеся postings**. Они переиспользуются по хешам.
Версия морфемной базы M в индекс не включается: I01 связывает лексемы, не морфемы.

Переиспользуются профили Э1 cs-pilot-source-r1, cs-pilot-unicode-r1 и
cs-pilot-letterfold-r1 — только если сервер реально поддерживает их неизменяемые
fingerprints. Display-only смена может переиспользовать токены, но требует своей
проекции и нового запроса/cursor. Corpus searchKey и словарный lookup/civilKey —
разные каналы: не считаем их строки тождественными и не переписываем нормализацию
во Flutter. Профиль выбирается явно через capabilities, не подменяется автоматически.

Новая выдача без I выбирает согласованный опубликованный манифест один раз.
Продолжение обязательно передаёт I и opaque cursor. Cursor связывает I/C/D/P,
канал, запрос или lexemeId, лимит, фильтры и текущий fingerprint доступности
источников. Клиент cursor не разбирает. Новый поиск после обновления — явное
действие; страницы разных публикаций не смешиваются.

Запрос lexeme требует dictionaryVersion=D из открытой карточки. Если такой
совместимой индексной публикации нет — 409 dictionary_version_mismatch, а не
нулевой счётчик и не автоматический переход к похожему написанию. Поиск формы
остаётся отдельным явным действием. Автоматический lookup Э1 не становится
подтверждённой корпусной связью. Для reader lookup в М2-04 нужны фактически
использованная D и поддержка точного выбора доступной D вместо скрытого latest.

Hit содержит pinned SourceAddress, occurrenceId, bodyRef, tokenIds, rawRanges,
matchKind, основание подтверждённой связи и snippet с точной картой либо явной
причиной его отсутствия. Переход использует существующий read/window и карту
этой ревизии. URL остаётся `/sources/id/{sourceId}?revision=…&passport=…&occurrence=…`.
Raw offset не добавляется как будто это зарегистрированный fragmentId;
поисковый GET не создаёт фрагменты в базе. Общее размещение адресуется постоянно,
точное слово дополнительно передаётся клиентским контекстом версий/токенов.

Смена видимости во время прохода даёт 409 visibility_changed; закрытые материалы
не попадают в сниппеты, названия или счётчики. Если нужные байты/проекции старой
публикации больше недоступны — 409 index_stale для индексной выдачи, а reader
возвращает предусмотренный 410 revision_unavailable. Нет тихого усечения покрытия.
Реестры, манифесты, паспорта и доступные I сохраняются до явного вывода из эксплуатации;
автоматического Sunset/удаления нет. Сохранённый manifest **не гарантирует старый raw**:
Э1 не копирует канонические тексты, native body после правки может стать недоступным
для прежней br1. Новые байты не выдают под старыми смещениями.

## Контракты и бюджеты выдачи

| Операция | Решение |
| --- | --- |
| GET index/capabilities | Реальные опубликованные I/C/D/P, publicRead, coverage, пределы и только реализованные features |
| GET index/search | pilotId, mode=word/phrase, q, profileSetId; I при закреплении/продолжении; без обещания лексемы |
| GET index/occurrences | pilotId, lexemeId, dictionaryVersion, profileSetId; I при закреплении/продолжении; только принятые связи |
| Reader catalog/resolve/read/passport | Переиспользуются существующие методы/DTO. Для каталога М2 добавляет точный catalogRevision=C и связывает его с cursor |
| Reader lookup | Переиспользуется выбор словаря, но кандидаты остаются unreviewed; точная D и строгая проверка вводятся М2-04 |
| Старый reader/search | Сохраняется прежний shape; после появления index/search помечается deprecated и может делегировать ему совместимую проекцию |

Первые пределы: page default 20/max 50, q до 200 UTF-16, phrase до 12 токенов,
проход до 500 **уникальных** hits. Сниппет — до 512 raw UTF-16 с полным совпадением
и границами графем; слишком длинное совпадение получает snippet=null с явной
причиной, а не обрезанный текст. Бюджет index-response — 1 MiB несжатого JSON.
Если бюджет сокращает страницу, nextCursor продолжает с первого ещё не выданного
hit. Если не помещается минимальный hit — явный 413.

После 500 hits при фактически обнаруженном продолжении: truncated=true,
nextCursor=null, hasMore=true и total.state=at_least. Без проверки ещё одного
hit нельзя заявить at_least или точный total. Exact total даётся только после
полного прохода; до него total.state=unknown. Число употреблений — счётчик
совпадений выбранного канала, не количество всех значений слова.

Ограничения reader из Э1 сохраняются: catalog 20/50, read 10/20 units,
lookup до 20 tokens, POST до 64 KiB, raw window до 65 536 UTF-16,
response до 4 MiB, manifest до 256 units. Не смешиваем эти пределы с лимитом
индексных hits. POST/search/occurrences и ошибки — no-store. Для capabilities
можно max-age=300; catalog/passport — ETag с обязательной ревалидацией доступа
(no-cache/must-revalidate), не безусловные старые 60 секунд публичного кеша.
304 возможен только после проверки доступа, версии и ETag; без сохранённого
тела клиент повторяет без условия. Полного offline в М2 нет.

## Совместимость, отказ и последующая работа

Ошибка индексного API имеет contract=cs-index/1 и error:{code,message,retryable,details}.
Число в HTTP-status и code проверяются отдельно. 404 namespace без envelope —
feature unavailable, а не пустой корпус; словарь М1 продолжает работать. 429
сохраняет Retry-After; 400 bad cursor, 409 mismatch/stale/visibility и 410 retired
не переключают версии или контракт автоматически. Неизвестные расширяемые поля
сохраняются/игнорируются, неизвестный обязательный variant останавливает точную
операцию. Аккаунт не предлагается как обязательное лечение обычного 429. Для web/портала
сохраняется CORS без credentials: публичные GET/POST/OPTIONS, доступные ETag,
Retry-After и X-RateLimit-*; cookie не требуется.

До включения мобильной функции нужно выполнить М2-02: сохранить reader/index
код, схемы, реальные реестры и тесты в версии репозитория; перенести только
проверенные реальные ID Э1, не synthetic fixtures; подтвердить текущие native
базы, видимость и SHA; собрать postings/проверенные связи, опубликовать согласованный
I и обеспечить эти правила доступа. Пустой/неполный реестр не объявляется ready.
Нельзя повторить ситуацию временного незафиксированного серверного API из М1-09.

М2-04 реализует отдельные DTO/ReaderRepository, сетевые правила М1-08, кеширование
и выбор возможностей; М2-03/05 подключают UI. М2-06 проверяет весь маршрут и
возврат. В М2-01 индекса, новой публикации C/I и интерфейса ещё не создаём.
Портальная точка входа остаётся в «Опытах», без главной/sitemap до отдельного решения;
публичный endpoint не равнозначен рекламе раздела на главной. Новая major-версия
контракта требует отдельного маршрута; cs-index/2 не возвращается молча на пути cs-index/1.

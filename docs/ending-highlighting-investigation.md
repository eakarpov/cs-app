# Почему пропадает выделение окончаний

Исходная диагностика: 11 ноября 2026 года, до исправления. Описанные ниже ответы относятся к прежней публикации. Исправление и новая база опубликованы в тот же день; см. [итог публикации](ending-segmentation-publication.md) и `qa/ending-segments-deployment-result.json`.

## Подтверждение на действующем API

Прочитаны две реальные карточки через `/api/v2/cs/lexemes/{id}`:

- `68399a217310e32be5d772b6`, воспо́льзовати: у `presSg2`, воспо́льзꙋеши, передано `segments: null`.
- `68399a217310e32be5d7654e`, безпеча́льный: у полного дательного безпеча́льномꙋ и краткого безпеча́льнꙋ передано `segments: null`. В полной начальной ячейке без̑печа́лный не размечено, а соседнее безпеча́льный имеет сегменты безпеча́льн + ый.

Flutter выводит подчёркнутое окончание только для переданных API сегментов `kind=ending`, при включённой настройке выделения окончаний. Для `segments=null` он выводит слово целиком. Таким образом, приведённые пропуски присутствуют до отрисовки таблицы.

## Найденные причины

1. **Опубликованные сегменты не соответствуют возможностям текущего сборщика.** Локальный вызов `paradigmsFor` на исходных нативных записях уже выдаёт воспо́льзꙋ + еши, безпеча́льн + ꙋ и безпеча́льн + омꙋ. В публичном API эти же формы всё ещё без границ. `DictionaryPublication.article` читает готовый JSON из SQLite и не пересчитывает сегменты. Обновление кода API или APK само по себе не обновляет сохранённые поля публикации. Точный исторический шаг сборки, впервые создавший эти `null`, не установлен; это не доказанная ошибка конкретного преобразователя ука.

2. **Граница ищется по всем основам лексемы сразу, без привязки к ячейке.** `segmentsFor` возвращает `null`, если подходят разные длины основы. Для видотвориши схемы V21n подходят видотвор- (окончание иши) и инфинитивная видотвори- (остаток ши). При этом шаблон `presSg2` использует первую основу с окончанием иши. Смешение основ разных ячеек создаёт устранимую неоднозначность. Выбор самой длинной или самой короткой основы вообще для всех форм был бы ненадёжным исправлением.

3. **Некоторые словарные варианты не совпадают с основой, вычисленной по основной лемме.** Без̑печа́лный не содержит мягкого знака из основы безпеча́льн-. Поэтому поиск точного префикса не находит границу, хотя для безпеча́льный находит. Новая таблица показывает первый обычный вариант в порядке API; в этой ячейке он без сегментов. Ранее пользователь мог видеть сразу несколько написаний, в том числе размеченное. Это отдельный вопрос от физического отображения подчёркивания. Нельзя незаметно исправлять написание словарной формы или считать его опечаткой только из-за несовпадения с основой.

4. **Для причастных таблиц сегментация явно отключена.** В `paradigmsFor` вызовы для `participle-brev` и `participle-plen` получают `allowSegments=false`. Поэтому отсутствие подчёркивания там ожидаемо для текущей реализации, даже когда окончания известны таблице склонения. Для исправления нужны основы самого причастия, а не механическое сопоставление с основами производящего глагола.

## Охват локального снимка

В диагностическом снимке 157 карточек, а не весь словарь. Без причастных парадигм:

| Часть речи | С сегментами | Без сегментов |
|---|---:|---:|
| Глаголы | 1185 | 1187 |
| Прилагательные | 1107 | 261 |

Это число записей форм во всех ячейках, включая дополнительные написания и повторяющиеся словоформы в разных падежах. Оно не является числом уникальных слов или оценкой всего словаря.

## Как исправлять

На сервере определять основу и окончание по шаблону конкретной ячейки. Для словарной формы принимать границу только при согласовании с этим шаблоном и точным исходным написанием; неподтверждённые случаи оставлять неразмеченными с явной причиной. Для причастий использовать их собственные парадигмы. Затем создать добавочное обновление `segments` поверх текущей публикации, сохранив формы, ударения, ID, словарные материалы и редакторские решения.

Контрольные примеры для исправления: -еши, -иши, -ꙋ, -омꙋ, краткие прилагательные с беглой гласной, словарные варианты с/без ь, причастия и возвратные формы. Конкатенация сегментов должна в точности восстанавливать форму; постфикс сѧ не должен попадать в окончание.

Машинный отчёт с ответами API: `qa/ending-highlighting-investigation.json`.

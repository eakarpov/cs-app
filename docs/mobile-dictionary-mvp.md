## Продуктовый фокус

Приложение помогает **найти слово или форму, разобраться в значении и грамматике,
проверить источник и вернуться к работе**. Расширение словаря должно улучшать
конкретные пользовательские запросы и карточки, а не только увеличивать счётчик.

Предлагаются две мобильные поставки:

| Поставка | Пользовательский результат | Основная зависимость |
| --- | --- | --- |
| **М1. Словарный MVP** | Удобный и достоверный словарь с управляемым пополнением статей, форм, разборов и связей | Существующее приложение, словарные API и процедуры публикации |
| **М2. Словарь с корпусным индексом** | Из статьи можно найти употребления, открыть контекст и паспорт, затем вернуться к слову | М1, подготовленная корпусная основа Э1 и выбранные задачи Э2–Э3 |

Э1-01–Э1-10 остаются завершённой технической основой корпусной ветки.
М1/М2 — новые обозначения мобильных поставок, **не перенумерация** Э1/Э2.
М2 включает начальный I01 раньше широкого исследовательского индекса Э3.

## Что переиспользуем

Поиск в двух направлениях, клавиатура, карточки источников, таблицы форм,
морфемы, этимологические свидетельства, смысловые связи, избранное, история
и настройки уже существуют. Они входят в регрессионную основу, а не в список
новых функций для повторной реализации.

Для корпуса уже есть reader API, адреса и декодер; мобильной интеграции ещё нет.
Полный текст остаётся у существующего владельца в библиотеке/певческой базе.
Словарные статьи, морфемные данные и корпусные паспорта не сливаются в одну
редактируемую копию.

Формулировки источников остаются раздельными. Если нужен краткий ориентир по
значению, он берётся из проверенного словарного содержания с указанием источника;
автоматически сочинённое общее толкование не входит в MVP.

Наличие статьи не требует полного набора морфем, этимологии или парадигм.
Недостающий блок показывается как пробел. Проверенный источник, автоматическое
происхождение и ручная проверка — разные признаки; один не заменяет другой.

### Навигация и основные сценарии

В М1 сохраняется нижнее меню **«Словарь / Связи / Энциклопедия»**. Поиск остаётся
первым экраном. Избранное/история и настройки используют существующие точки входа;
регистрация не становится условием поиска или сохранения слова.

1. Запрос → объяснимый результат → карточка → форма/источник → возврат
   к прежней выдаче без потери запроса, направления и прокрутки.
2. Нет результата → сохранить введённое написание → сообщить о недостающем слове
   с необязательным контекстом → получить подтверждение отправки.
3. Карточка → избранное → повторное открытие по стабильному lexemeId после
   обновления данных. Недоступная статья обозначается явно.
4. Морфема или связанное слово → просмотр → возврат к исходной карточке
   и выбранному варианту без смешивания омонимов.

Вариантный поиск не раскрывает титла произвольно и не склеивает слова только
потому, что нормализованные строки совпали. Новый алгоритм неизвестной формы S05
остаётся последующей задачей; здесь улучшаем поиск и покрытие известных данных.

### Расширение словаря как повторяемый процесс

| Шаг | Результат |
| --- | --- |
| Сбор пробелов | Ненайденные запросы и замечания, отсутствующие источники/формы/разборы. Неотправленный личный поиск не передаётся как заявка без действия пользователя |
| Разбор очереди | Определён тип: новое слово, вариант, словоформа, омоним, ошибка карточки, недостающий источник или разбор |
| Проверка источника | Прочитана полная статья/свидетельство, сохранены источник и локатор, проверены условия использования |
| Идентификация | Найдена существующая лексема либо обоснован новый ID; варианты и омонимы не объединяются по похожему написанию |
| Пополнение | Добавлены нужные статьи, формы, грамматика, морфемы или связи с независимыми пометами происхождения и проверки |
| Решение | Принято, отложено, отклонено или оставлено как кандидат; причины и альтернативы сохранены |
| Публикация | Валидация, сравнение изменений, активация версии и возможность отката; ручные решения переживают повторный импорт |
| Мобильная проверка | Изменённая карточка и поиск проверены через тот же публичный API, которым пользуется приложение |

Редакторская работа в М1 выполняется через существующие серверные/исследовательские
процедуры и минимальную очередь. Полноценный кабинет редактора, роли сообщества
и редактирование статьи из телефона не требуются для первого выпуска.

Приоритет пополнения: воспроизводимые ошибки поиска и привязок → пропуски в
востребованных карточках → проверенные новые слова/формы → дополнительные
морфемные, этимологические и семантические сведения. Массовые кандидаты могут
составлять отдельный слой, но не повышают счётчик редакторски проверенного покрытия.

Это приёмочная выборка, **не лимит словаря и не обещанное число новых слов**.
Первый пакет содержит выбранные реальные пробелы; его размер фиксируется после
источниковой проверки, отдельно от объёма тестов.

## М2: корпусный индекс внутри словарного приложения

М2-01 [зафиксировал границы доступа и выдачи](m2-01-public-index-contract.md); М2-02 [реализовал локальный индекс и адресные связи](m2-02-pilot-index.md). [Серверная публикация завершена 17 ноября](m2-02-unicode17-publication.md): Unicode17/r2, прежние ID и четыре решения сохранены, публичный HTTPS проверен. APK не публиковался. Визуальная приёмка М1 не подменяется этой спецификацией.

Основной вход — **«Употребления» из карточки слова**. Дополнительный раздел
**«Тексты»** даёт каталог и поиск по пилоту. Предлагаемое нижнее меню М2:
**«Словарь / Тексты / Связи / Энциклопедия»**.

Маршрут: статья → употребления → контекст → текст/паспорт → слово → статья
с возвратом на прежнее место. Словарь остаётся стартовым разделом.

Начальный индекс — I01: написания, формы и проверенные связи с лексемами,
поиск слова/фразы, адресуемые вхождения и ограниченная выдача по пяти материалам.
Указатели лиц, мест, тем, понятий, хронология и общий граф не входят в М2.

М2 группирует существующие задачи корпусной ветки; их результаты не выполняются
второй раз под новыми ID. Начальный I01 переносится в мобильную поставку раньше
полного исследовательского Э3 — это уточнение приоритета.

Пустая выдача значит «не найдено в проиндексированном пилоте», а не отсутствие
слова во всех текстах. Совпадение формы не выдаётся за проверенное употребление
лексемы или её значения. Одно и то же вхождение ссылочного ирмоса, открытое через
две карточки источника, не увеличивает число употреблений; реальные разные места
сохраняют свои occurrenceId.

Сохраняются raw, профили нормализации и карты UTF-16 из Э1. Для офлайна либо
хранятся согласованные версии тела/паспорта/карты, либо явно требуется сеть.
Недоступная старая версия показывает отказ и отдельный выбор текущей версии,
а не молчаливую замену. Портальная часть пилота остаётся в «Опытах» до отдельного
решения о её публичном размещении.

## Границы первого словарного выпуска

В М1 не включаем полный offline-словарь, обязательный аккаунт и синхронизацию,
учебные курсы/SRS, универсальный разбор неизвестного слова, массовую автоматическую
этимологизацию, новый редакторский кабинет и полную миграцию корпусного reader.

Личные списки, заметки, экспорт учебных наборов, новые словообразовательные
отношения и расширенные тематические подборки — отдельные последующие задачи
S10/S19/U/F08. Они могут войти небольшим дополнением после М1-09, но не блокируют
первый словарный выпуск. Энциклопедия сохраняется; её массовое расширение также
не блокирует словарную работу.

## Как принимаем результат

Для М1 фиксируем успешность контрольных запросов, восстановленные корректные
переходы, исправленные/новые карточки и формы, число проверенных привязок,
остаток очереди и сохранность личных данных. Числа до/после считаем по одной
выборке и раздельно для reviewed/unreviewed; исходный диагностический срез
сохранён в М1-01, критерии экранов — в М1-02.

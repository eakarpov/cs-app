Ниже сохранён результат проверки до применения.

«Готово» означает проверку тождества лексемы, значения и соответствия ссылке
по доступным материалам. Это не независимая научная экспертиза этимологии:
Викисловарь нередко сам цитирует ЭССЯ. Десятки повторений одного текста
у производных слов не считаются десятками подтверждений.
Подготовленные ссылки имеют тип `attested-in` и ограниченную область
`historical-source-correspondence`: они не утверждают прямое наследование,
единственную реконструкцию или происхождение всех значений статьи.

## Почему отклонены 57 пар

| Основание | Пар | Пример |
|---|---:|---|
| Усечение многословного заголовка до первого слова | 38 | `ob bоkъ` ошибочно превращалось в `ob` |
| Неподходящий омоним proto-статьи | 8 | `искони → konьcь II` (лошадка); `обличити → obličiti II` (считать) |
| Совпало другое значение нашей лексемы | 5 | `коръ` — библейская мера, а не укор; `ленъ` — растение, а не ленивый |
| OCR-омограф заголовка | 3 | `kора` со статьёй о копне, `kоръ` со статьями о копании / копоти |
| Противоречие реконструкции содержанию | 1 | `молити → molditi`: статья о `младити`, а не о молитве |
| Конфликт части речи | 1 | Наш ID `ѡ` — INTJ, историческое `о / ob` — предлог |
| Страница-указатель вместо словарной статьи | 1 | interlex 342: фонд на начальные фонемы `ak-` |

Отклонение относится к конкретной паре ID. Например, наличие ошибки
`молити → molditi` не отменяет этимологии слова `молити`; оно требует поиска
другой статьи. ID предлога `о` нельзя подменять существующим ID междометия.

- `import/wiktionary-reviewed/package-final/review-85.html` — все 85 пар,
  фильтры решений, значения нашей статьи и контексты обоих источников.
- `import/wiktionary-reviewed/typikon-final/review.merged.json` — отдельный

  Исходные поля, отношения, отклонения и локальные редакторские данные сохранены.
- `import/wiktionary-reviewed/typikon-final/plan.json` — контрольные суммы,
  входные условия, список изменений и порядок будущей безопасной публикации.
- `data/wiktionary/review-85.json` — закреплённые решения для каждого ID пары
  и SHA-256 исходных материалов. Для принятых ссылок подготовлены отдельные
  пользовательские пояснения; внутренние причины проверки не подмешиваются в UI.

В merged-файле `etymologyReviewDecisions` хранит все решения, а
`etymologySources` — неизменяемые исходные записи. В каждой ссылке `provenance`
связывает её с этими записями и проверенными цитатами. Нынешний сборщик
передаёт ссылки с дополнительными JSON-полями без потери; Flutter использует
прежние поля, структурированное происхождение остаётся в данных.

## Защита и проверки

Подготовка выполняется без команды применения: SQLite открывается с `mode=ro`,
создаются только новые выходные файлы. Перед подготовкой проверяются хеши
исходного набора и доказательств, версия публикации, payload каждой из 17 статей,
ID / заголовок / тело proto-статьи, целостность пакета и точность текстовых смещений.
Изменение схемы или локальной правки входит в изменение payload и останавливает
подготовку. Конфликт с редакторским решением или источником также останавливает
подготовку. Прежние этимологические ссылки не заменяются автоматически.

Повторная подготовка на уже объединённом файле добавила **0** ссылок,
сохранила все **25** и дала побайтно одинаковый JSON. Пройдены **45 тестов**:
11 проверок импорта и 34 проверки извлечения / сопоставления / сохранности.
Проверки на уменьшенных SQLite-фикстурах подтверждают блокировку изменённых
и отсутствующих целей и отсутствие записи при чтении.

Для следующего прохода исправлены три причины ложных кандидатов: усечение
многословных заголовков, принятие указателя за статью, перенос общего происхождения
через переход к сравнению «ср.» / «сюда же». Проверка повторяемости теперь работает
во временной папке и сохраняет оригинальные артефакты даже при расхождении.
Снимок прежней пробы не переписан; остальные 1 002 пары этим аудитом не проверялись.

Перед будущей публикацией требуется свежая сверка серверных данных и текущего
редакторского файла, резервная копия, сборка отдельного кандидата и сравнение
всех ID, схем, локальных правок и существующих источников. Финализатор typikon-web
также перерабатывает морфологию и отношения: готовый merged-файл является
входом отдельного сборочного прогона, а не поводом запускать его над рабочей базой.
Версия и хеши фиксируются в плане; смена данных требует повторной подготовки.

Повторная живая сверка выполнена только GET-запросами: версия API typikon-web
совпала со снимком, заголовки и SHA-256 тел всех 16 используемых proto-статей
совпали с interlex. Это сверка на момент подготовки, не замена проверке перед
будущим релизом. Протоколы: `live-version-check.json` и `interlex-live-check.json`
в папке пробы; итог также сохранён в `qa/wiktionary-review-85-summary.json`.

Команды воспроизведения: `tool/wiktionary_review/README.md`.
